## Анализ текущей архитектуры

1. **Синхронные REST-запросы к сервису "ins-product-aggregator"**  
  - Каждый запрос к сервису "ins-product-aggregator" требует ожидания ответов от всех страховых компаний. Из-за этого ответы могут приходить с задержками, замедляя работу сервисов "core-app" и "ins-comp-settlement".
  - Если не изменить архитектуру, то при росте числа страховых компаний время ответа увеличится.

2. **Проблемы с масштабированием**
- Сейчас сервис работает с 5 страховыми компаниями, но планируется подключение ещё 5 компаний - это приведет к увеличению нагрузки на "ins-product-aggregator".

3. **SLA API не соответствует заявленным требованиям**
- Отдельные партнеры "сжирают" все ресурсы.
- Если не внедрить Rate Limiting, то другим партнерам так и не будет хватать ресурсов.

4. **Сайт медленно загружает страницы**
- Из за того что сервис "core-app" работает в синхронном режиме, он может быть недоступен в момент обращения к страковым компаниям. Поэтому веб приложение не может получить информацию о доступных продуктах.
- Если не изменить архитектуру, то при росте числа клиентов положение дел будет только хуже.
